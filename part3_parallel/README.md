# Часть 3. Многопоточная и многопроцессорная обработка

## Структура

- `app/producer_consumer.py` - поток-производитель (сканирует каталог) + потоки-потребители
  (читают файлы в массивы numpy), обмен через `queue.Queue`, общий счётчик защищён `threading.Lock`
- `app/augment.py` - аугментация (поворот, отражение, шум) + пул процессов (`multiprocessing.Pool`,
  `apply_async` с `callback`)
- `app/performance.py` - сравнение времени последовательной и многопроцессорной аугментации,
  сохранение `performance_report.json`
- `app/main.py` - точка входа, собирает всё вместе

## Запуск

Из папки `part3_parallel`:

```
python -m app.main --path ../data/input/part3_sample --consumers 3 --processes 4 --report performance_report.json
```

## Результат на тестовых данных

24 изображения 96×96: последовательно 0.087 с, через 4 процесса - 1.0 с (ускорение 0.09, то есть
медленнее). 200 изображений 256×256: последовательно 2.71 с, через 8 процессов - 3.74 с (ускорение
0.73). Объяснение - в отчёте (раздел "Часть 3"): сама аугментация через numpy уже векторизована и
выполняется в C с освобождением GIL, поэтому полезной работы на процесс слишком мало, чтобы окупить
накладные расходы на создание пула процессов.
